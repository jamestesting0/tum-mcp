# Verify Exam

1. **Report**: after building, read `tum-mcp study exam-report PROJECT`. Resolve stale
   items, review low-confidence and out-of-scope questions, and decide every flagged
   target: revise it or keep it with a reason in your report. Read the coverage report's
   `cheatsheet` section: every gap, unrecorded source and unrequested entry is fixed or
   reported.
2. **Content**: re-solve every changed answer, drill and forecast question; compare each
   cheatsheet line with its source; confirm every pattern workflow solves each listed
   instance, each instance falls under exactly one case of a decision step, and every
   case is worked once in the examples and practised again in the drill. Every variable
   meaning names what the variable is in this pattern (or, on the cheatsheet, in general)
   and no meaning only renames it. Read each
   answer next to only what its question has shown so far; anything it names must be in
   the question, a prompt or the starter code.
3. **App**: open the changed views with `tum-mcp study` at desktop width (phone only
   when asked). Check that cheatsheet lines read clearly without opening them,
   opened tables, code and diagrams fit,
   the map labels are legible, a guided past question works through its steps, and every
   practice-exam question opens its own solution. App behaviour itself is covered by
   the package's tests; report a suspected app defect instead of editing the app.
4. **Report** honestly: checks run, gaps (missing years, unreadable scans, unofficial
   solutions), kept outliers. A build does not prove correctness, and no check proves
   what the next exam contains.
