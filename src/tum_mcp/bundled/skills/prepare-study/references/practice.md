# Practice that tests a useful decision

Start with the reasoning demand, then solve the item independently before writing
options. Add an item for a distinct objective, misconception or transfer demand;
remove paraphrases that test the same decision. No fixed bank size or difficulty quota.

Choose the demand that fits the goal:

| Demand | Evidence it can provide |
| --- | --- |
| Recall | Retrieve a condition, definition or invariant before reveal |
| Discrimination | Choose between plausible methods using the actual constraints |
| Composition | Combine familiar inferences without a step naming each method |
| Reverse or premise | Infer a missing input or explain which assumption a claim needs |
| Changed case | Adapt reasoning when a meaningful condition or representation changes |

Changing names or numbers while naming the same method does not establish transfer.
A useful progression might pair a trace with a choice of method and a changed
assumption. Keep only the members that teach or test different decisions.

Every question must stand alone in both topic Practice and pooled Revision. Put the
situation it is about in the question's `blocks` (the graph with its weights, the table,
the formula, the code); the build rejects a question without one. Include notation, units
and assumptions the answer depends on. A reference to “the graph above” breaks when the
item is pooled. An optional `hint` recalls the idea without naming the option.

Write four distinct options by default; the schema sets the accepted range. Map
each distractor to a plausible reasoning error, and verify every option under the
stated assumptions. Revise ambiguous premises; never force a key. The app shows options
in a stable shuffled order. Match option length/style; avoid joke options
and all/none shortcuts. If no further meaningful option exists, change the task
rather than adding filler.

Wrong-answer feedback identifies the earliest likely reasoning break and gives a
small repair or recheck. Do not repeat the full solution for every distractor.
The correct explanation should derive the result and name its limiting condition.
Do not infer a diagnosis from one click or treat an immediate corrected retry as
independent success. A later fresh item can give better evidence; no retention
scheduler or mastery score is required.

Use prepared Exercises for proofs, coding/design reasoning or open construction
that deserves a rubric. Compare valid alternative reasoning fairly. Never label
ungraded prose correct or claim that Reviewed proves understanding.
