# Recovery and adoption

`study status` never writes. A recover result retains any readable course summary;
inspect the known project state/instruction paths implicated by its reason first. Missing/edited managed instructions
are a conflict to reconcile with their saved hash, not a new course. Preserve user
rules outside the block. Never change the saved hash to bypass a conflict.
Never copy source material into executable agent rules. For a symbolic project
root, verify and use its canonical path while leaving the link untouched.

For damaged state, retain the original bytes. Restore a validated same-course
backup only when its course identity and managed paths can be verified; then rerun
status. Do not fabricate revisions, replace state with an empty inventory, or remove
state to make initialization succeed. If no trustworthy recovery is available,
report the gap and continue independent reads; preserve the original project.

For missing state with existing unmanaged files, confirm the course/semester from
connected metadata and inspect ownership before adopting the directory. A first
snapshot may reference verified local sources; initialization still uses its
normal conflict checks. Existing managed markers without a matching state require
recovery first. A failed write is not permission to delete material and retry.

After recovery or verified adoption, follow [snapshot reconciliation](project.md).
